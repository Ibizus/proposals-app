# Generic tax configuration instead of country-specific engines

The original salary calculation was hard-coded around Portuguese tax concepts (IRS brackets by marital status and dependents, fixed Social Security rate, 14 yearly payments). The captain now lives in Spain and wants the app to demonstrate a generic, configurable tax model rather than maintaining per-country payroll engines.

We decided to replace the Portugal-specific `Taxes` entity with a `TaxConfiguration` that holds the number of yearly payments and a list of `Tax` entries. Each tax is either a fixed rate, a list of progressive brackets, or a withholding table; each extra or salary item declares which taxes apply to it (or none, when exempt). Marital status and dependents were removed from the tax model; candidate fields were left untouched. Bundled Spain and Portugal configurations are preloaded as illustrative example data, with Spain as the active default. Extra templates are scoped to a tax configuration so that extras created from a template reference taxes that exist in that configuration.
